Struct StaticPalette 

Source 
pub struct StaticPalette<N: 'static, T: 'static> { /* private fields */ }
Expand description

A const-constructible Palette alternative: name/color pairs stored in a &'static slice and looked up by linear scan.

Palette itself can never be built in const contexts - its HashMap needs a runtime-seeded RandomState. For static theme tables (a handful of colors per theme) the linear scan of StaticPalette is as fast as hashing, needs no allocation and is fully const-evaluable. Convert into the hash-backed Palette via Palette::from when lookup volume justifies it.

use smearor_commons_color::Color;
use smearor_commons_color::StaticPalette;
use smearor_commons_color::palette_definition;
use smearor_commons_color::static_palette;

palette_definition! {
    /// Square colors of a board theme.
    pub enum BoardSlot {
        /// Light squares.
        Light => "light",
        /// Dark squares.
        Dark => "dark"
    }
}

static BOARD: StaticPalette<BoardSlot, u8> = static_palette! {
    BoardSlot::Light => Color::<u8>::new(0xED, 0xD4, 0x9E),
    BoardSlot::Dark => Color::<u8>::new(0x73, 0x4D, 0x2E),
};
assert_eq!(BOARD.get(&BoardSlot::Light), Some(&Color::<u8>::new(0xED, 0xD4, 0x9E)));

Since the entries live in &'static storage, keys must be const-evaluable and drop-free - fieldless enums generated by crate::palette_definition!, &'static str or integers. crate::NamedColor cannot be used here: its Cow name has a destructor, which prevents static promotion.
