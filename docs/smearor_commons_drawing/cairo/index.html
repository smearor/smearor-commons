The cairo backend: CairoTarget implements the shared capability vocabulary on a cairo::Context.

Feature-gated behind cairo and headless-safe — cairo-rs alone pulls no display dependency, so this backend is testable without a compositor. Backend-specific extras stay reachable through CairoTarget::context instead of widening the shared traits.

  • target: the owning CairoTarget itself
  • surface: ViewSurface and readback — bridges buffer memory and cairo ImageSurfaces
  • path: generic cairo path building blocks (polyline, spline, wave, band, rounded rect, tile fill)
  • glyph_path: crate-internal ab_glyph outline → cairo path replay used by the icon and text capability impls
  • <cap>_ops: one file per capability trait — the cairo backend has a single target type, so no per-target directory split
  • error: DrawingError for bridging failures outside cairo’s own status model

image_surface_from_buffer
Copies a [PixelBuffer]’s pixels into a fresh ARgb32 [ImageSurface] — the inverse of pixel_buffer_from_surface. Channels are converted through the [PixelFormat] interface: whatever the source format, each pixel is re-encoded as premultiplied BGRA (the ARgb32 memory layout).
pixel_buffer_from_surface
Copies an ImageSurface’s pixels into a packed [PixelBuffer<BgraPremultiplied>], honoring the surface’s stride (cairo may pad rows beyond width·4).
